# Translating cheats.rs

English is the source language. Its existing files and URLs stay unchanged.
Translations use Zola's native suffix convention: `cargo.fr.md` corresponds to
`cargo.md` and is published at `/fr/tooling/cargo/`. Brazilian Portuguese uses
`pt-BR`, including the capitalization in filenames and URLs.

## Create a language

Install Node dependencies and Zola 0.20.0, then run:

```sh
npm install
npm run i18n:add -- fr
```

The command registers the language in `config.toml`, creates `i18n/fr.json`,
and creates translated Markdown files beside the originals. Pages start with
`draft = true`; section indexes start with `render = false`. Repeating the
command never overwrites existing content. `i18n:sync` adds only missing pages
and message keys.

Translate the catalog's **values**, not its keys. Keep placeholders such as
`{number}` and `{count}` unchanged. The catalog includes the language's display
name, `dir` (`ltr` or `rtl`), and `ready`. Set `ready` to `true` only after every
interface message has been translated. Code examples remain in their original
language; do not translate Rust keywords, identifiers, string literals, comments
inside executable examples, or API names.

Translate each page's `title`, `description`, `extra.seo_title` when present,
and prose. Keep filenames, weights, `extra.anchor`, HTML IDs, input names,
shortcode parameters, and diagram structure unchanged. Translate diagram prose,
but preserve code and byte values. For Markdown headings, retain the original
fragment explicitly, for example `## Visão geral {#overview}`.

## Publish gradually

Enable the translated home and the required category indexes with `render = true`.
Remove `draft = true` from finished pages. The language selector appears when the
home and interface are ready. Sections and pages without translations remain
available through links explicitly labeled as English. The previous/next buttons
visit published topics in the current language only. Search and alternate-language
metadata exclude drafts.

Internal links should retain the original identity and fragment. Shared navigation
resolves translations from the publication manifest. The final HTML postprocessor
also resolves links in topic content, using the English original with a language
label when its translation is unavailable. External documentation links keep their
original destinations. Do not add custom page paths to translations; the print
source's explicitly prefixed path is the one exception generated by the tool.

## Keep translations current

```sh
npm run i18n:sync -- fr
npm run i18n:status -- fr
npm run i18n:reviewed -- fr tooling/cargo.md
```

Status reports missing files, drafts, and source changes. `source_hash` covers
source prose and translated metadata; it is recorded when a draft is created.
After comparing the translation against the current source and making any needed
edits, `i18n:reviewed` updates that hash. It does not translate or publish anything.
Source changes generate review warnings rather than deleting a published translation.
The hashes in `scripts/content-integrity.json` independently protect the audited
English content.

## Preview and validate

```sh
npm run dev
# Final output, including search filtering, link resolution and table enhancements:
npm run build
python3 -m http.server 4173 --directory public
```

`dev` watches content, catalogs and configuration and regenerates the publication
manifest. `build` prepares it before invoking Zola. For direct Zola commands, first
run `npm run i18n:prepare`. The generated `data/i18n.json` is ignored by Git.
It contains language availability, source identities, localized metadata and routes;
never edit it manually. Templates render messages from `i18n/<code>.json`, and
browsers and the postprocessor consume the same catalog.

```sh
npm run check:i18n
npm run test:i18n
npm run check:content
npm run check:design
npm run check:site
npm run check:reading -- http://127.0.0.1:4173
npm run check:i18n-browser -- http://127.0.0.1:4173
npm run check:a11y -- http://127.0.0.1:4173
npm run check:lighthouse -- http://127.0.0.1:4173
```

The fixture test scaffolds a third language in a temporary copy and builds a
partially translated site. It checks idempotence, publication, missing messages,
placeholder validation and source revisions. Browser tests cover both Chromium
and Firefox. Review translated prose and visual diagrams in addition to automated
checks: structural checks cannot establish linguistic or technical accuracy.

## PDFs

After a fresh build, package the output and generate PDFs:

```sh
bash scripts/ci_pack_public.sh
npm run pdf
npm run check:site -- public.clean --final
```

English downloads retain `/dl/rust_cheat_sheet_a4.pdf` and the Letter equivalent.
Translated downloads use `/<code>/dl/`. A language becomes eligible for PDFs when
all 42 printable topics are published. Its translated `print-source.<code>.md`
must also be published. The generator removes all internal `_print` directories
from the final package, and search and sitemaps exclude these sources.

## Brazilian Portuguese glossary

| Source concept | Convention |
| --- | --- |
| cheat sheet | guia de referência |
| ownership | posse |
| borrowing / borrow | empréstimo / emprestar |
| borrow checker | verificador de empréstimos (`borrow checker`) |
| binding | vínculo |
| trait / lifetime / closure | trait / lifetime / closure; explain in Portuguese when useful |
| slice / array | slice / array |
| string / thread / crate | string / thread / crate |
| memory layout | organização da memória |
| pattern matching | correspondência de padrões |
| destructuring | desestruturação |
| cast / coercion | cast / coerção |
| undefined behavior | comportamento indefinido (UB) |
| sound / unsound | válido / inválido quanto às garantias de segurança; retain sound/unsound when distinguishing concepts |
| unsafe | preserve `unsafe` when referring to Rust's keyword or permission boundary |

The initial pt-BR translation was machine-assisted locally, with editorial
corrections to interface text, metadata and technical explanations. Further
contributions should follow this glossary and compare prose with the English
source rather than treating a successful build as proof of translation quality.
